# 固定汇报格式

以下占位符必须替换为本次已核实的信息；示例不是审核结果。正文不添加总结标题、评分、表格或额外营销措辞。

```text
{月}月{日}日审核同步

未完成人员名单；@{姓名} @{姓名}

作品1 @{作者}
这篇帖子的优点是{基于已读作品的具体优点}；缺点是{有依据的不足或改进空间}。

作品2 @{作者}
这篇帖子的优点是{具体优点}；缺点是{具体不足}。

……

明日审核人：@{姓名}
审核情况：{原审核表链接}
```

## 内容规则

- 标题日期直接来自“审核日期”。例如审核日期为 `2026-10-28`，标题就是 `10月28日审核同步`；不要因为实际在别的日期执行而改标题。
- 缺交名单按原审核表名册顺序排列，每个人都加 `@`。确认全部提交时写 `未完成人员名单；无`；名单或记录未读全时写 `未完成人员名单；待核对`，不能以“无”代替未知。
- 每篇先写作品编号和 `@作者`，下一行是一段连贯点评。至少有一个作品独有的细节支撑评价，优点和不足都不强行套模板。确实未发现有依据的明显缺点，可写“缺点是目前未见明显问题，可进一步……”并只给作品相关的优化建议；不得凭空编造缺陷。
- 默认最多五位不同作者。实际可读少于五篇时只写实际篇数，在执行说明中列出缺少原因；用户指定更多、少于五篇或指定作者时遵照要求。不得用 `……`、占位符或虚构作品补齐正式结果。
- 明日审核人按原轮值顺序确定；确认不了时写 `明日审核人：待确认`，不要写 `@待确认`。实际“明日”日期可以在执行说明中交代，不额外改变报告模板。
- “审核情况”使用审核表链接，而不是作品提交表、个人临时文件或其他同学的表。链接暂缺时写“待补充”，不要构造一个网址。
- `@姓名` 是可复制的文本，不代表已经触发群聊提醒。

## 报告之外的执行说明

完整在线任务可简写：`执行说明：已核对全部 N 人；目标日期 N 格已刷新核验。实际执行日为 YYYY-MM-DD，明日为 YYYY-MM-DD。`

有异常时，先用一句话标明结果性质，再给报告正文，并另列最短必要说明。例如：

- `以下为材料审核汇报，依据提供的名单和全文生成，未在线核验、未回填原表。`
- `以下为审核草稿：提交记录尚未读取完整，缺交名单和原表回填待完成。`
- `执行说明：N 人已确认提交，M 人确认缺交，K 人待核对；已核验 X 格，Y 格保存状态未确认。`
- `执行说明：指定作者的作品无法完整访问，本次未生成该篇点评。`

不要把访问失败、材料模式、回填失败或缺少轮值规则隐藏在一份看似已完成的汇报里。只对有证据的步骤称“完成”，其余说明具体缺什么和下一步由谁处理。
