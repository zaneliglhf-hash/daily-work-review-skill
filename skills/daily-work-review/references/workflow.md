# 在线审核流程

需要实际读取共享文档或填写原审核表时阅读本文件。使用当前执行器支持的连接器或浏览器操作工具，不依赖某次任务的页面 ID、坐标或固定行号。

先落实 [表格操作边界](write-safety.md)。读取时也不得键入区域地址或测试文字；如用户已要求停止操作原表，停止本流程，不以核验或修复为由重新打开。

## 1. 识别文档与权限

- 打开用户提供的链接，核对标题、用途、相关页签和文档类型，区分“作品提交明细”与“审核/完成情况”。先在明确入口查找缺少的另一张表，没有入口才问用户。
- 确定目标日期如何表示、应提交人员范围、作品链接所在字段，以及轮值名单位置。有明确的免交或退出人员规则时据此处理，否则不擅自剔除人员。
- 只有查看权限时仍可继续读取和生成结果，但明确不能回填。需要登录、扫码、验证码或权限选择时交给同学处理，不尝试绕过。
- 确定筛选是否影响所有协作者；优先使用个人视图。不能为了读记录而修改共享筛选或重排原表。
- 把用户填写的审核日期与实际表头、目标记录日期逐一核对。若任务标题写一天、拟处理的列却是另一天，按用户明确填写的审核日期检查冲突；不能按执行日自动减一天或沿用上次列号。

## 2. 读取目标日期的全部提交

- 采用日期字段的实际含义筛选，不把上传时间、发布时间、补交所属日期混用。明确有“所属审核日期”的记录按该字段处理；含义不明的跨日记录先核实。
- 检查所有页、折叠组、加载区域与有效行数。若表格采用 Canvas，可使用工具支持的截图、原生复制、导出或记录详情；不能仅因页面文本里没有某人就判缺交。
- 看见筛选标记却无法确认筛选条件、分页或加载是否完整时，未匹配人员一律待核对，不写 ❌、不列为确认缺交；不能用“仅按可见记录判断”的备注替代完整性核验。
- 复制或导出后，核对表头、行数、首尾记录与目标日期，防止使用旧剪贴板或错误选区。发现来源不一致时重新读取。
- 建立内部核对表：姓名、记录/行定位、日期依据、作品入口、提交状态、阅读状态、目标回填位置、核验结果。不需要复制整篇作品，也不要收集任务无关的账号信息。
- 区分 `已提交`、`确认未提交`、`待核对`。完整读取后才能生成缺交名单；总人数应能与这三类人数对上。同名多条提交去重，表外记录和别名疑问单独核实。

## 3. 阅读与点评

- 先确定点评对象，再逐一打开原链接。默认按提交表顺序选不同作者，指定作者则遵照指定范围。
- 读完正文、展开被折叠内容，并查看内容图片。记录标题和一两处能支持点评的具体细节；只见到标签、摘要或封面时不能当作全文。
- 同一作者有多篇时，默认点评按表顺序第一篇能完整阅读的作品，并保留所选入口的证据。用户明确指定某篇时不自行替换。
- 无法阅读时，先完成必要的登录或正常重试；同一步连续失败两次后记录阻碍，继续可独立完成的部分，不无限刷新或绕过访问限制。
- 输出每篇的优点和不足，不预测未经验证的流量、互动或转化数据。可以说明某种表达可能引发的阅读感受，但不能说它已经带来了实际效果。

## 4. 原表回填

本节必须按 [表格操作边界中的回填步骤](write-safety.md#3-逐格回填与停止条件) 执行。先核实本次白名单及外部权限限制，再进行真实业务写入；首格验证不是任意编辑测试。权限保护或目标绑定无法确认时，输出逐人待回填清单，保留原表。

`待核对` 人员不写 ❌。保存无法确认或第一次出现目标、焦点、边界异常时停止全部写入；不适用读取时的“两次重试”规则。仅把刷新后核验一致的格记作已保存。

## 5. 汇报与恢复

- 用核对后的记录生成报告；审核日期决定标题，实际执行日期用于“明日”，原轮值顺序决定下一位审核人。
- 有必要时在用户工作空间的 `.daily-work-review/runs/` 保存最小任务证据：本次三个字段、执行时间、已核对范围、作者/作品入口、阅读细节、回填前后状态与待办。它是本地私有材料，不进入技能发布包。
- 中断后从证据继续，但先确认在线数据未变。目标日期、文档链接或审核人改变即视为新的任务，不沿用旧缺交结论或旧轮值结果。
- 返回固定格式报告和单独的执行说明；没有在线读取或保存证据时，不声称在线审核和原表回填全部完成。
